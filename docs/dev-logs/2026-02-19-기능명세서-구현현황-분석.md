## 핵심 개념 설명

### 기능 구현 완료 판단 기준
- **완료**: 프론트엔드 화면 + 백엔드 API + 양쪽 연동이 모두 이루어진 상태
- **부분 구현**: 한쪽만 있거나, 양쪽 다 있지만 연동 미완성
- **미구현**: 코드 자체가 없는 상태

### 스침 판정 배치가 미구현인 이유
- 앱의 핵심 매칭 로직이지만 Spring Batch 의존성 자체가 없음
- `encounters` 테이블은 마이그레이션으로 생성됨 (데이터 삽입 로직만 필요)
- 위치 전송 API는 구현되어 있어 데이터는 수신 가능한 상태

### FCM 푸시 발송이 미구현인 이유
- FCM 토큰 등록/저장은 완료 (fcm_tokens 테이블)
- 프론트엔드 FCM 수신 처리도 완료
- 백엔드에서 FirebaseMessaging.send() 호출하는 서비스만 없음

## 새로 배울 수 있는 것
- 기능명세서와 실제 코드 대조 방법: 화면(Screen) → 서비스(Service) → API 연동 순으로 추적
- MVP 관점에서 핵심 vs 부가 기능 구분: 스침 판정이 없으면 매칭 자체가 불가
- 프론트/백 양쪽 구현 상태를 동시에 파악해야 전체 완성도를 정확히 판단 가능

## 리스크 및 주의사항
- **스침 판정 미구현**: 현재 앱을 실행해도 실제 매칭이 일어나지 않음 (수동으로 relationships에 데이터 넣어야 테스트 가능)
- **FCM 미발송**: 인연 신청/수락 등의 알림이 실시간으로 전달되지 않음
- **영수증 stub**: 현재는 모든 결제가 성공으로 처리됨 (테스트에는 편리하나 프로덕션에서는 위험)
